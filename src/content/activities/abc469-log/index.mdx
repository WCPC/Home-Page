### C問題

<details>

<summary>問題文を表示</summary>

<div style="background-color: #f5f5f5; padding: 15px; border-radius: 5px; border: 1px solid #ddd;">

**問題文**<br />
`o` と `x` からなる長さ $N$ の文字列 $S$ が与えられます。<br />
$N$ 個の袋が一列に並んでいて、各袋にはお菓子が $1$ 個ずつ入っています。<br />
$i$ 番目の袋には、$S$ の $i$ 文字目が `o` ならば「当たり」と書かれており、`x` ならば「はずれ」と書かれています。<br />
$k=1,2,\dots,N$ について以下の問題を解いてください。  <br />
> 高橋君は列の先頭から $k$ 個の袋を受け取り、入っているお菓子を食べ、袋は持っておきます。<br />
> その後、以下の行動を可能な限り繰り返します。<br />
> 
> * 高橋君が持っている「当たり」と書かれた袋を $1$ 個捨て、列の先頭の袋を受け取り、中のお菓子を食べてその袋を持っておく。ただし、列にまだ袋が残っていて、かつ「当たり」と書かれた袋を持っている場合にしか行動はできない。<br />
> 
> 高橋君が食べることのできるお菓子の個数を求めてください。<br />
> 袋を受け取った場合、その袋は列から取り除かれることに注意してください。


**制約**<br />
- $1 \leq N \leq 8 \times 10^5$
- $N$ は整数
- $S$ は `o` と `x` からなる長さ $N$ の文字列

**入力**<br />
入力は以下の形式で標準入力から与えられる。<br />
$N$  <br />
$S$  <br />


**出力**<br />
答えを合計 $N$ 行で出力せよ。<br />
$l$ 行目には、$k=l$ のときの答えを出力せよ。<br />

</div>

</details>

k = 1, 2, ..., N について順番に答えを求めます。

まず重要な考察として、 k が増えると食べられるお菓子の個数は単調に増加します。 k = m のとき食べられるお菓子の個数は k = m - 1 のときよりも（少なくとも1つ）多いです。これを利用して解きます。

まず、列の何番目まで食べることができたかを記録する `right` という変数をおきます。初期値は0にします。その後、

1. `k` に関するループの始まりです。
2. `right = min(right + 1, N)` をします。
3. `right == N || S[right - 1] == 'x'` ならば `right` の値を出力して `k` を進め、1. に戻ります。
4. そうでないなら2. に戻ります。

この方針をそのまま実装したコードが[こちら](https://atcoder.jp/contests/abc469/submissions/78516007)です。(C++)

#### ちなみに

[公式解説](https://atcoder.jp/contests/abc469/editorial/23762)はもっとスマートに解いています。

実は、食べられるお菓子はぴったり k 番目の'x'までです。よって、'x' の位置を調べるとこの問題を解くことができます。

具体的には N 要素の配列をNで初期化し、 "k 番目の'x'の添え字 + 1" を配列の k - 1 番目に入れます。（ 配列・文字列の添え字は 0-indexed ）最後はその配列を出力するだけです。

### D問題

<details>

<summary>問題文を表示</summary>

<div style="background-color: #f5f5f5; padding: 15px; border-radius: 5px; border: 1px solid #ddd;">

**問題文**<br />
あるゲームには $N$ 人のプレイヤー $1,2,\dots,N$ がいます。<br />
このゲームは $2$ 人のプレイヤーが $1$ 対 $1$ で戦う形式です。<br />
$N$ 人のプレイヤーによるトーナメント戦が $M$ 回行われ、$m$ 回目のトーナメント戦の決勝にはプレイヤー $A_m,B_m$ の $2$ 人が勝ち上がりました。<br />
以下の条件を満たすような $2$ 整数 $x,y$ の組がいくつあるかを求めてください。  <br />
$1 \leq x \lt y \leq N$<br />
どのトーナメント戦においても、プレイヤー $x$ とプレイヤー $y$ の少なくとも一方が決勝に勝ち上がっている<br />

**制約**<br />
- $2 \leq N \leq 2 \times 10^5$
- $1 \leq M \leq 2 \times 10^5$
- $1 \leq A_i \lt B_i \leq N$
- 入力される値はすべて整数

**入力**<br />
入力は以下の形式で標準入力から与えられる。<br />
$N$ $M$  <br />
$A_1$ $B_1$  <br />
$A_2$ $B_2$  <br />
$\vdots$  <br />
$A_M$ $B_M$  <br />


**出力**<br />
答えを $1$ 行で出力せよ。<br />

</div>

</details>

[公式解説](https://atcoder.jp/contests/abc469/editorial/23759)の方がきれいに解けると思いますが、今回は[自分のコンテスト中に出した解法](https://atcoder.jp/contests/abc469/submissions/78042471)の解説をします。

#### 前置き

入力が

```
5 3
1 2
3 4
1 4
```

の時を考えてみると、条件を満たす (x, y) の組は (1, 3), (1, 4), (2, 4) の3組です。

入力が

```
5 2
1 2
1 3
```

の時、条件を満たす (x, y) の組は (1, 2), (1, 3), (1, 4), (1, 5), (2, 3) の5組です。

入力が

```
5 2
1 2
1 2
```

の時、条件を満たす (x, y) の組は (1, 2), (1, 3), (1, 4), (1, 5), (2, 3), (2, 4), (2, 5) の7組です。

というような調子で入力に対する答えを手作業で求めていくと、最も組の総数が多くなるのは $A_i, B_i$ がそれぞれすべて同じ時のような気がしてきました。その時の組の総数は $(N - 1) + (N - 2) = 2N - 3$ 通りであり、 N が最大のケースでも $4 \times 10^5 - 3$ 程度です。

組数の上限がその程度であれば、条件を満たす組をすべてsetに入れたり、queueに入れたりしてもメモリ超過しないです。また、私の解法で行った、毎回候補を全部queueに入れて更新する方法が、ワイルドカードを使って工夫することで実行時間内に間に合います。

#### 解法

queueに候補を入れ、毎回全ての候補を見て候補を更新していきます。簡単のため、queueに入れる候補となる組はfirst &le; secondにします。

そして、 $A_i, B_i$ より**十分に大きい数**をワイルドカード（どの数にもなることを表す）定数`WILD`として宣言しておきます。大きくするのは`WILD`をできるだけ組のsecond側にするためです。また、候補を入れるqueueは事前に (`WILD`, `WILD`) を入れておきます。


$A_i, B_i$ の添え字 i をfor文で回し、次の手順で処理を行います。

1. 候補のqueueの要素数を変数`sz`に入れます。
2. `sz`回のループを始めます。
    1. まず、候補のqueueの先頭の組のfirstを`f`、secondを`s`という変数に代入します。その後、先頭はpopします。
    2. `f` == `WILD`ならば候補のqueueに ($A_i$, `WILD`), ($B_i$, `WILD`), ($A_i$, $B_i$) を入れます（初回の処理）。
        * `f` == `WILD`のとき、`f` &le; `s`より`s` == `WILD`でもあります。つまり、候補 (f, s) はどちらの要素もワイルドカードなので、ここから出る候補は上記の3つになります。
    3. `s` == `WILD`のとき、`f` == $A_i$ または `f` == $B_i$ ならば、候補のqueueに (`f`, `WILD`) を入れます（ワイルドカードの継続）。そうでないなら (`f`, $A_i$), (`f`, $B_i$) を入れます（ワイルドカードの終了）。
    4. `f`も`s`もワイルドカードではないとき、`f`,`s`に $A_i$, $B_i$ と同じ値があれば候補のqueueに (`f`, `s`) を追加します（候補継続）。
        * `f`,`s`に $A_i$, $B_i$ と同じ値がなかった時は候補のqueueに何も追加されないので、候補は棄却されたことになります。

最後に、queueに入っている候補すべてをsetに入れて重複を除きます。ここで`WILD`を復元します。具体的には (`f`, `WILD`) がある場合に N - 1 個の組 (`f`, i ) をsetに入れます。（ i は1以上 N 以下かつ`f`ではない整数）

これで全ての条件を満たす組がsetに入れられたので、答えはsetの要素数になります。

#### 計算量

最初の (`WILD`, `WILD`) からは ($A_i$, `WILD`), ($B_i$, `WILD`), ($A_i$, $B_i$) の3つが候補となり、 (`f`, `WILD`) からは (`f`, $A_i$), (`f`, $B_i$) の2つが候補になります。また、 (`WILD`, `WILD`), (`f`, `WILD`) 以外からは最大で1つの候補しか出ないので候補数が増えることはないので、候補のqueueの要素数は最大で5個です。

よって、添え字 i について M 回ループを回しても十分高速です。

最後のsetに入れる処理も、入れる要素数が最大で $2N - 3$ 個であることから $O(N \log N)$ の計算量で済みます。

#### 食塩水典型とは？

確かなことは分かりませんが、濃度などを答えで二分探索するテクニックで解くときに、「濃度がp以上」という式の変形を使って問題を解く典型だと思います。

今回のE問題の記事を書くにあたって、名前のもとになったと思われる先に[ABC034 D - 食塩水](https://atcoder.jp/contests/abc034/tasks/abc034_d)を解いてみました。（解けなかったので解説を読みました）

食塩水はどういう問題だったかというと、

<details style="background-color: #f5f5f5; padding: 15px; border-radius: 5px; border: 1px solid #ddd;">
<summary>（ネタバレ防止）</summary>

i 番目の食塩水の食塩が $s_i$ グラム、 溶液全体が $w_i$ グラムとします。

1. にぶたんの式を変形します。濃度をp%以上にできるか？という条件式は、 $p/100\le(\sum^K_i s_i)/(\sum^K_i w_i)$ となるわけですが、ここで、次のように変形できます: $0\le\sum^K_i(s_i-w_ip/100)$
2. 配列を用意し、全ての $s_i, w_i$ について $s_i-w_ip/100$ が計算できるので、計算して配列に入れてソートします。
3. ソート結果で値が大きいものからK個とり、総和が0以上かどうかを判定します。これが二分探索の判定部分で、計算量は二分探索の反復回数をXとして $O(XN \log N)$ です。よって、十分高速なのでこの問題を解くことができました。

</details>

#### 今回の問題の食塩水と違うところ

今回の問題と食塩水の明らかに違うところは、連続する区間を選ぶ必要があるというところです。

食塩水の問題は連続する区間を選ぶ必要がなかったのでソートが有効でした。しかし、今回はそれが使えません。

ところが、連続する区間を選ぶことで使えるようになることもあります。それは累積和です。ということで、今回は累積和を使います。

#### 解法

※ここからは公式解説と同じ解法を書いています。

食塩水の問題と同じように $s_i-w_ip$ を使います。今回の $s_i$ は S[i] == 'o'ならば1、そうでないなら0です。また、 $w_i$ は常に1です。

今回は連続する区間を選ぶので $\sum_i(s_i-p)$ の計算に累積和が使えます。つまり、区間 i までの累積和を $P_i$ 、選んだ区間を[r, l]とすると、 $\sum_i(s_i-p)=P_r-P_{l-1}$ が成り立ちます。このとき、0以上を達成するためには $P_r$ が大きく、 $P_{l-1}$ が**小さくなっていた方が嬉しい**ことは明らかです。

これらのことを使うと、次のようにしてこの問題を解くことができます。

1. p を決めます。
2. $s_i-p$の累積和をとります。
3. $s_i-p$の累積和の累積minをとります。
4. 尺取り法を用いて各 r に対する最大のlを調べます。この l は、区間 [l,r] で K 勝以上する l です。
5. r に関するループを回して r を全探索します。そして、前の手順で調べた r に対応する l における累積minを $M$ とし、$P_r-M$ が0以上かどうかを調べます。

以上の5手順が二分探索の判定部分です。この処理の計算量は $O(N)$ なので、二分探索の反復回数を X として、全体の計算量は $O(NX)$ になります。二分探索の反復回数は十分少ないと考えられるので、実行制限時間内に解くことができます。
