### C問題

<details>

    <summary>問題文を表示</summary>
    <div style="background-color: #f5f5f5; padding: 15px; border-radius: 5px; border: 1px solid #ddd;">
    	**問題文**

    	文字列 $S, T$ が与えられます。
    	$Q$ 個のクエリを処理してください。
    	クエリでは $L, R$ が与えられるので、$S$ の $L$ 文字目から $R$ 文字目までからなる部分文字列に、$T$ が部分文字列として含まれるかを判定してください。

    	部分文字列とは<br/>
    	$S$ の**部分文字列**とは、$S$ の先頭から $0$ 文字以上、末尾から $0$ 文字以上削除して得られる文字列のことをいいます。
    	例えば、`ab` は `abc` の部分文字列ですが、`ac` は `abc` の部分文字列ではありません。

    	**制約**

    	- $S$ は長さ $1$ 以上 $4 \times 10^5$ 以下の英小文字からなる文字列
    	- $T$ は長さ $1$ 以上 $10$ 以下の英小文字からなる文字列
    	- $1 \leq Q \leq 2 \times 10^5$
    	- $1 \leq L \leq R \leq |S|$
    	- $Q, L, R$ は整数

    	**入力**

    	入力は以下の形式で標準入力から与えられる。

    	$Q$<br/>
    	$S$<br/>
    	$T$<br/>
    	$\mathrm{query}_1$<br/>
    	$\mathrm{query}_2$<br/>
    	$\vdots$<br/>
    	$\mathrm{query}_Q$

    	各クエリ $\mathrm{query}_q$ は以下の形式で与えられる。

    	$L$ $R$

    	**出力**

    	$Q$ 行出力せよ。$q$ 行目には $q$ 番目のクエリについて、$S$ の $L$ 文字目から $R$ 文字目までからなる部分文字列に、$T$ が部分文字列として含まれれば `Yes` を、含まれなければ `No` を出力せよ。

    </div>

</details>

文字列 $S$ の指定された部分文字列に文字列 $T$ が含まれるか判定する問題です。

部分文字列として含まれるかだけを判定するのなら簡単なのですが、この問題は指定された区間内に含まれるかを判定しないといけないため少し難易度は上がります。

用いた解法は $S$ 内の $i$ 番目の位置から文字列 $T$ が作れるかどうかを前計算で判定しておき、$i$ 番目から文字列 $T$ が作れる場合は 1 、そうでなければ 0 となるような配列を作成します。
あとは任意区間について 1 となるような値が 1 つでも存在すれば $T$ が存在することを示せるので、その判定を行うために累積和を取り任意区間の総和が 1 以上かどうかという判定を行うことで解きました。

### D問題

<details>

    <summary>問題文を表示</summary>

    <div style="background-color: #f5f5f5; padding: 15px; border-radius: 5px; border: 1px solid #ddd;">
    	**問題文**

    	$N$ 個のマスが横一列に並んでおり、左から順にマス $1$ からマス $N$ までの番号がついています。色は英小文字で表されます。

    	はじめ、すべてのマスの色は `a` で、各マスには何も置かれていません。

    	$Q$ 個のクエリが与えられるので、与えられた順に処理してください。各クエリは以下の $2$ 種類のいずれかです。

    	- `1 X` : マス $X$ にタイルが置かれていなければタイルを置き、置かれていれば取り除く。

    	- `2 C` : タイルが置かれていないすべてのマスの色を $C$ に変更する。


    	すべてのクエリを処理した後の各マスの色を（タイルが置かれているかどうかにかかわらず）求めてください。

    	**制約**

    	- $1 \le N,Q \le 3\times 10^5$
    	- 各クエリはタイプ $1$ またはタイプ $2$ のいずれか
    	- タイプ $1$ のクエリにおいて、$X$ は $1 \le X \le N$ を満たす整数
    	- タイプ $2$ のクエリにおいて、$C$ は英小文字 $1$ 文字

    	**入力**

    	入力は以下の形式で標準入力から与えられる。

    	$N$ $Q$<br/>
    	$\mathrm{query}_1$<br/>
    	$\vdots$<br/>
    	$\mathrm{query}_Q$

    	各クエリ $\mathrm{query}_i ~ (1 \le i \le Q)$ は

    	$1$ $X$

    	または、

    	$2$ $C$

    	の形で与えられる。

    	**出力**

    	最終的な各マスの色を、左から順につなげた長さ $N$ の文字列として出力せよ。
    </div>

</details>

最近大体のD問題がよくある問題だなと思ってきたのですが、これもまあ典型ですね。と言いつつ、ぱっと見分からず先にE問題解いたのですが...

クエリタイプ 1 の処理は $\mathcal{O}(1)$ 、2 の処理は $\mathcal{O}(N)$ です。そのため極端な場合、2 の処理しかなければ $\mathcal{O}(NQ)$ になり間に合いません。
この問題で求めなければいけないものはクエリを処理した後の最終的なマスの色です。このことから**クエリの途中に各マスがどんな色になっているかは分からなくてもよい**、つまり各マスごとに最後に塗られた色のみを覚えておけばよいと分かります。

これは**クエリを逆順に見ていく**というテクニックを用いることで解けます。逆順に見ていくと各マスが何色になるかが確定していくので、まだ色が確定していないマスの集合を保持しながら色を確定させていけば解くことができます。

この問題ちょっと意地悪で、Java で HashSet を使って提出したのですが、TLE になり C++ に書き換える必要がありました。この好プレーで一応 AC することが出来ました。
コンテスト後なんでダメだったのかなと考えていたのですが、この問題は集合に対してループする処理を行う必要があり、集合が保持している要素数に対して実際の内部配列のサイズは多くなっているため、そこで重くなったのかなと。
結果的に Java のコードでも TreeSet や他のデータ構造だと通ったため、HashSet に対する拡張 for 文は十分に気を付ける必要があるなと思いました。良い学びです。

### E問題

<details>

はい。 D よりも先に解いた問題です。問題を見て解法がすぐに思いつかなかったのですが、ダイクストラを使いたいなという気持ちを持ちながらボードにお絵かきして考えていました。
**E 問題は典型のアルゴリズムやテクニックをどう適用するかみたいな問題が多い**なという印象で、今回もダイクストラを使いたいという気持ちが答えとなる発想に繋がったと思います。

こういった難しい問題に挑むにあたって大事なことは**簡単な問題条件に変えて、絶対にわかることから潰していくこと**です。早期判定をいっぱい作ることで、解くべき問題を明確にすることができ自然と解法を導くことができます。

まず頂点 $N+1$ が無い場合を考えます。この場合は左回りか右回りの 2 通りになり、どちらの方がコストが低いのかを考えるだけです。
次に頂点 $N+1$ を絶対に通る場合について、頂点 $N+1$ を通って他の頂点に行った後、もう一度頂点 $N+1$ に戻ってくることは明らかに不要です。
したがって、頂点$N+1$を通る場合はある頂点 $U$ から何らかのルートで頂点 $N+1$ に行き、頂点 $N+1$ からまた別のルートを通って頂点 $V$ に行くというルートになります。

この時自分が考えたのは、他の頂点から始まっても**頂点 $N+1$ から次の頂点への最短経路を求める必要がある**から、ここをダイクストラしておけばとりあえず半分は消せるなーと。
.....ああ逆から見ても同じか！？となって、ある頂点から頂点 $N+1$ に行くというルートも頂点 $N+1$ を始点とするダイクストラを最初にしておけば、$U$ -> $N+1$ 間も $N+1$ -> $V$ 間も $\mathcal{O}(1)$ で求められるということが分かりました。
後は頂点 $N+1$ を通る場合とそうでない場合（左回りか右回りか）の比較を行うだけで解くことができます。

### F問題

<details>

    <summary>問題文を表示</summary>

    <div style="background-color: #f5f5f5; padding: 15px; border-radius: 5px; border: 1px solid #ddd;">
    	**問題文**

    	$N$ 行 $M$ 列のグリッドが与えられます。上から $i$ 行目では、左から $L_i$ 列目から $R_i$ 列目までのマスが黒く塗られており、それ以外のマスは白く塗られています。

    	$Q$ 個のクエリが与えられます。各クエリでは、以下の問題に答えてください。

    	- 整数 $A,B,C,D$ が与えられます。上から $A$ 行目から $B$ 行目まで、左から $C$ 列目から $D$ 列目までの長方形領域に含まれる黒いマスの個数を求めてください。

    	**制約**

    	- $1 \le N,M,Q \le 2\times10^5$
    	- $1 \le L_i \le R_i \le M$
    	- 各クエリについて、$1 \le A \le B \le N$
    	- 各クエリについて、$1 \le C \le D \le M$
    	- 入力される値はすべて整数

    	**入力**

    	入力は以下の形式で標準入力から与えられる。

    	$N$ $M$ $Q$<br/>
    	$L_1$ $R_1$<br/>
    	$L_2$ $R_2$<br/>
    	$\vdots$<br/>
    	$L_N$ $R_N$<br/>
    	$\mathrm{query}_1$<br/>
    	$\vdots$<br/>
    	$\mathrm{query}_Q$

    	各クエリ $\mathrm{query}_i ~ (1 \le i \le Q)$ は

    	$A$ $B$ $C$ $D$

    	の形で与えられる。

    	**出力**

    	$Q$ 行出力せよ。$i$ 行目には、$i$ 番目のクエリに対する答えを出力せよ。
    </div>

</details>

ここからはコンテスト中には全く分からなかったのですが、コンテスト後に解説ACすることが出来たので書いていこうと思います。
本当はコンテストから時間も経ったのでこの記事自体書くつもりがなかったのですが、この問題は初めての解法だったので書く価値があるなと思い書いています。

何から説明すべきか難しいのですが、問題を整理するとまず $N$ 行 $M$ 列のグリッドとあり、これは $NM \ge 10^{10}$ であるためデータとして保持することはできないなと考えます。
ではどうやってグリッドの情報を表現し、クエリを処理していけばよいかというと、まずあるクエリ $q$ に着目し $A_q$ 行目から $B_q$ 行目までの行について、$C_q$ 列目から $D_q$ 列目までをループして探索するのではなく、**1 列目から $D_q$ 列目までの黒マスの総数**から**1 列目から $C_q-1$ 列目までの黒マスの総数**を引くということを考えます。

こうすることで $\mathcal{O}(N)$ 必要だった処理が、$\mathcal{O}(1)$ になります。これはグリッドの情報を行ごとに **1 列目からの累積情報**として持っていれば可能です。
この **1 列目からの累積情報**というのが重要で、現在処理している列を $x$ とし、ある行 $i$ について 1 列目から $x$ 列目までの黒マスの総数の求め方を以下の3通りの条件に分けて整理することでどのように持てばよいかが見えてくると思います。

1. $x < L_i$ の場合は $0$
2. $L_i \le x \le R_i$ の場合は、$x - L_i$
3. $R_i < x$ の場合は、$R_i - L_i$

これを列ごとに全ての行を更新することなく管理する方法を考えます。ここで出てきている値について、$0$, $L_i$, $R_i$ は定数であることから、一度 $x$ を忘れて定数部分の遷移だけみると、各列ごとに毎回値を変える必要はなく初期値を 0 として $L_i$, $R_i$ の場所で 2 回この定数を変えるだけでよさそうです。
またこの定数部分は各行ごとに求める必要があり、さらにその任意区間の総和（行$A$ ~ $B$ までの区間和）が欲しいのですが、これは **セグメント木** を使うことで簡単に求めることができます。

状態2については、この状態になっている行だけ $x$ を加算させることを考えます。これも同様に **セグメント木** を用いることで $x$ を加算するべき状態 2 の個数として求めることができます。

最後に列ごとに処理を行いたいので、$L$, $R$, $C$, $D$ を全てソートして 1 列に並べたときに適切にイベント（現在見ている値がクエリの左端なのか右端なのか、黒マスの開始か終了か）を処理すれば解くことができます。

</details>

前提知識として、Mo's Algorithm が必要で、そのうち**木上のMo**とかいうアルゴリズムを使えば簡単に解くことができる問題です。
ライブラリ化してしまえば誰でも解けるため、もっとdiffが低くてもおかしくないのではと思うのですが、そもそもレアなアルゴリズムで使いどころも見極めづらいのかなと思います。

木上のMoについての話をすると、まず使える前提としてクエリの問題でありそのクエリはそれぞれ独立していて、並び替えが可能であり、木上の任意の2頂点を結ぶパスに対してのクエリであるということです。
そしてそのパスに頂点が追加されたり、削除されたりした際の状態の変化が $\mathcal{O}(1)$ やそれに近いオーダーの場合に使用できます。

必要な知識としては、Euler Tour, LCA, Mo's Algorithm かなと思います。
